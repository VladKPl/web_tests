## Реализовано, но ещё не проверено полностью

Локальный запуск через Selenium Manager; весь набор в обоих браузерах; генерация HTML через Allure CLI; новые проверки имени. Финальные прогоны выполняются, результаты будут добавлены ниже.

## Ограничения / не реализовано в полном объёме

- Диагностика логов намеренно сохраняет только level/timestamp; подробные сетевые события не сохраняются.
- Скриншоты показывают фактическое состояние UI; не вводите реальные секреты.
- Очистка аккаунтов реализована в штатных сценариях и finally заказа; при аварии во время регистрации до подтверждения создания аккаунта возможен оставшийся тестовый аккаунт.
- Проверки безопасности ограничены обычным UI, это не аудит защищённости сайта.
- Адресные значения пока фиксированы в SignupPage и проверках CheckoutPage.
- Не все вспомогательные операции из ТЗ реализованы (например, удаление отдельного товара из корзины).

## Ручное действие

Для HTML-отчёта требуется установить Allure Commandline по README. Java обнаружена, allure в PATH отсутствует. Для remote-тестов ручных действий не требуется.

## Новый сценарий: некорректный email

Требование: форма не должна продолжать регистрацию с адресом без @.
Правка: LoginPage.verify_invalid_signup и параметризованный test_registration_validation.
Проверка: testexample.com и test@ отклонены Firefox; проверены checkValidity, validationMessage и сохранение страницы входа. Аккаунт не создаётся. Это HTML-валидация, не проверка серверного API.

## Технические решения

Сохранены базовые ожидания, локаторы и переходы архива, исправлены импорты. Новые страницы отделяют Selenium от сценариев. Driver function-scoped, уникальные данные и UUID файлов обеспечивают независимость. Ошибки не превращаются в skip/успех. Измерения охватывают бизнес-методы и ожидания, status отражает исключения; вложенные длительности не складываются. Официальный Compose сохранён без ненужных изменений.
